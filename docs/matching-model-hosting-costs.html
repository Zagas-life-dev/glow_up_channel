What each model costs on GCP

Every model from the shortlist, priced for 10,000 calls/day — 304,200 calls/month — in us-central1.

$0.00 / month

That is the honest compute cost of every embedding model on the list at this volume. 10K calls/day is small enough that all of them — from 8M parameters to 595M — fit entirely inside the Cloud Run free tier, on requests, on vCPU-seconds and on GiB-seconds simultaneously.

The model you pick is not the cost driver. How you keep it warm is. The same workload ranges from $0 to $147/month depending only on deployment shape, and the spread between the cheapest and most expensive model is smaller than the spread between two ways of hosting the same model.

The number that actually matters

$0.00 assumes scale-to-zero. At 0.116 req/s your service will idle out overnight and cold-start — loading a 300 MB model takes seconds. Avoiding that is where the money goes.

The counterintuitive result: the managed Vertex AI embedding API is cheaper than self-hosting any of these models on always-warm infrastructure — $2.92/month against $12–147. Serverless per-token pricing wins decisively at low volume because you are not paying for idle.

That flips as you scale. Vertex is linear in calls; a VM is flat. Break-even against a $12.23 e2-small is roughly 42,000 calls/day; against a $48.92 e2-standard-2, roughly 167,000/day. Below those lines, managed is cheaper and less work.

The cheapest call is the one you don't make

Worth stating plainly, because it changes the premise: at 10K feed requests/day you probably do not need 10K embedding calls.

Listings are embedded once at ingest. A user's profile vector only changes when they edit their profile — which is rare. Cache it on the profile document and the per-request embedding count drops to roughly zero; every feed render becomes pure cosine arithmetic, which is what lib/nlp/similarity.ts already does for free.

naive     10,000 feed requests/day  ->  10,000 embeddings/day
cached    10,000 feed requests/day  ->  ~50 embeddings/day   (profile edits only)

This also matters for a reason that is not cost. The known latency problem on this feed is round trips — ~240 per request at 296 ms RTT. Adding a network hop to an embedding service on every render would make the actual bottleneck worse while saving nothing. Precompute; do not call.

What I would do: run EmbeddingGemma-300M as a batch job at ingest to vectorise listings, cache profile vectors on write, and skip the online embedding service entirely. Budget is then effectively $0 — batch ingest fits in the Cloud Run free tier or costs a few cents on Vertex batch.

If you do want a live endpoint, start with Vertex AI at $2.92/month rather than standing up a container. Move to an e2-small at $12.23 if you cross ~40K calls/day or need a model Vertex does not host. Do not reach for Cloud Run min-instances=1 — it is the most expensive option here and buys nothing a $12 VM does not.

Line items I have left out

  • Egress — ~$0.12/GB. 304K responses of a 256-d float32 vector (1 KB) is ~0.3 GB, about $0.04/month. Negligible, and zero if ranking stays in-process.
  • Artifact Registry — ~$0.10/GB/month for container images. A 2 GB image is $0.20/month.
  • Ingest embedding — one-off. 50,000 listings × 500 tokens = 25M tokens = $3.75 on Vertex, or $1.88 batch. Free on Cloud Run.
  • Vector storage — 50,000 × 256 dims × 4 bytes = 51 MB. Stored on the existing Mongo documents, so no new line item. Managed vector databases would be a new one, and are not needed at this corpus size.
  • GPU — deliberately omitted. Nothing on this list needs one, and the cheapest Cloud Run GPU would exceed every figure on this page combined.

Caveats. The per-call latency estimates are the weak link: they are scaled from parameter counts and architecture, not measured on GCP hardware, and could be off by 2–3× in either direction. That barely matters for the conclusion — the embedding models have roughly 7× headroom before any of them leaves the free tier, so even a 3× miss keeps every one at $0.00. It matters much more for the reranker rows, where the figures are already non-zero and scale directly with candidate count. Prices are us-central1 list, Tier 1, September 2026, before any committed-use or sustained-use discount, and cloud pricing changes without much notice; re-check before committing spend. Free-tier allowances are per billing account, not per service, so a busy project elsewhere would eat into the headroom that makes these numbers zero.
