Fixed on the branch

CRITICALAnyone could send email as UP

POST /api/marketing/send-campaign had no sign-in check. The only gate was the admin page hiding itself. One request could mail any list from UP's verified sender.

Fix: the route now asks the backend who the token belongs to and allows super admins only (lib/server/require-super-admin.ts). Recipients are validated and capped at 500 per send. The admin page now sends its token.

HIGHAnyone could spend the Gemini key

POST /api/marketing/ai-generate was open with no length limit.

Fix: same super-admin gate; subject capped at 200 characters, body at 5,000.

HIGHFounder Batch accounts could edit or delete listings nobody owns

The ownership check was skipped when a listing had no owner, which is every ingested listing. Six places: job update and delete, event delete, opportunity delete, resource update and delete.

Fix: no owner now means admin only. src/controllers/{job,event,opportunity,resource}Controller.js

HIGHPublishers could approve their own listing

Create routes copied isApproved from the request for non-admins, so "isApproved": true skipped moderation. Four controllers.

Fix: non-admin creates are always unapproved. Behaviour change, see Questions.

HIGHJob update could steal ownership and forge view counts

The update built the job from the request body; providerId and metrics came from the caller.

Fix: both are now kept from the stored job. src/controllers/jobController.js

HIGHAny signed-in user could read every provider's onboarding record

GET /api/provider-onboarding/admin/all returned email, phone, address, registration number and document link with no role check.

Fix: requireAdmin added; the open /admin/test debug route removed. src/routes/providerOnboarding.js

HIGHPassword reset code could be guessed

The 6-digit code came from Math.random, and the 5-attempt cap was read and incremented in two steps, so parallel guesses all passed it.

Fix: crypto.randomInt; each guess claims an attempt in one atomic update before the compare. src/services/passwordResetService.js

HIGHOpen routes stored ids of any size

POST /api/feed/anonymous/engage saved anonId uncapped under a 10 MB body limit. About 50 requests could fill the 512 MB cluster and block production writes.

Fix: anonId must be 1 to 64 letters, digits, _ or -; visit sessionId must be a string of at most 128.

MEDIUMSmaller fixes

  • Founder Batch payment check accepted a transaction with no user on it. Now the transaction must name this user. founderBatchController.js
  • JWT verify now pins HS256 in all four verify calls. middleware/auth.js, utils/jwt.js
  • Open redirect: /login?callbackUrl=/%09/evil.com passed the check. Control characters and backslashes are now rejected, with 3 new test cases. lib/pending-intent.ts
  • Listing links: cleanUrl returned javascript: URLs unchanged. It now returns empty for script, data, file and blob schemes. lib/url-utils.ts
  • Push tap could open another site if the payload url was //host. The service worker now opens this origin only. public/sw.js
  • Security headers: none were set. Added frame blocking (X-Frame-Options, frame-ancestors 'self'), nosniff, Referrer-Policy, HSTS. next.config.mjs
  • Log leak: a profile update logged the whole user object, password hash included. Line removed. authController.js
  • Connection string in source: scripts/cleanup-all-indexes.js and readMe.md no longer hold one. The old values stay in git history until rotated.

Checked and fine

  • Monitor role: cannot write; empty assignment reads nothing; ?monitorId= honoured for admins only.
  • Sign-up role is fixed to seeker; profile, playlist, event and opportunity updates are whitelisted.
  • Role and active status are re-read from the database on every request; a deleted user's token fails.
  • Passwords: bcrypt cost 12. No JWT secret fallback; the server exits without one.
  • Mongo operator injection: express-mongo-sanitize is global; user-fed regexes are escaped.
  • Internal cron routes and the push worker: constant-time secret check, closed when the secret is unset.
  • Upload keys: 256-bit, stored hashed, user re-checked per request, revocable.
  • Frontend: one raw-HTML sink, and it escapes; no open proxy or image fetch of user URLs; no secrets in NEXT_PUBLIC_*; .env* and key files never committed in the frontend repo.
