Round 2: everything you approved

Deprecations

  • Channels, community posts, connections, old notifications. Removed from both repos (backend routes, controllers, models, feedAlgorithmService, hashtagAffinityService; frontend pages and components). Trimmed to match:
    • Profile: no Partner button, no saved posts. Each profile view runs 4 fewer Mongo queries.
    • Listing pages: no community "Post" button.
    • Playlist hashtags now open Discover search.
    • Settings: the Privacy tab is gone (it only controlled connections).
  • Locked In. Removed from both repos: route, page, context, reminder method, XP keys and the settings toggle.
  • Promotions billing. Promotions were separated from billing first. Then wallet, Paystack top-up, payments, receipts, the bank-transfer flow and the admin receipts page were removed. Free start, admin grant and the other live promotion paths still work. Kept: paystackService (founder batch uses it) and /api/webhooks (Paystack posts there).
  • Dead code: 61 orphan frontend files, 27 frontend packages (pnpm), 3 backend packages, 68 uncalled API client methods, the subscription proxies, and unused routes: rotation, public stats, promotion expiry admin, /api/email, WWU stats, promotions-demo, under-construction.
  • Root clean-up: 30 old docs moved to docs/archive/; one-off scripts deleted; 307 brag-output* files and the Scraper gitlink untracked (the files stay on disk).

Bugs

  • Unescaped user input in search filters (company, location, category, admin searches): (a+)+$ took 46.5 s on one short string; now 0 ms. A lone ( no longer causes a 500.
  • ESLint: 4 errors → 0 (story icons go through one StoryIcon component).
  • Guest taps: save, like and playlist taps after a dismissed popup did nothing. They now show a toast with a Sign up button.
  • Sign-up keeps the guest's place: the page and the tap are remembered through login, sign-up, email verification and onboarding, and the save is replayed after sign-in. Date of birth stays on the sign-up form on purpose: it is the 13+ age check the Terms rely on.

Speed

  • Background jobs that never ran: the dead-items sweep, metrics reconciliation and daily stats snapshot are now push-worker jobs (00:30, 02:00 and 02:30 UTC), once per day in total.
  • Discover: the pool is cached for 60 s and shared, and each card carries 6 preview items. Before: 624–1,100 ms and 288 KB. After: a cache hit skips the 2 biggest reads; size expected ~25 KB (not measured until deployed).
  • Browser caching: promoted rails 30 s, guest stories 5 min (signed-in readers stay no-store, so the holdout is safe), FX rates 1 h.
  • Duplicate route prefetch removed (20–24 requests per page).
  • Detail pages no longer re-download a listing the server already rendered (~300 ms each).
  • Landing page no longer downloads the feed's ranking code: the 115 KB taxonomy chunk is out of / (checked in the build manifest).
  • Stories readout starts at launch (3 Nov), so there is no fake "unknown" surface.

Growth

  • Guest-apply 50/50 test on job, opportunity and event pages.
    • Arm "wall": today's "Sign in to apply".
    • Arm "open": the real Apply button, then "Did you apply? Track it", which leads to sign-up and tracking.
    • Readout: guestApplyTest in the maintenance analytics (applies and sign-ups per arm).
    Checked locally against a stub API.
  • Push ask after a save or apply ("Remind you before it closes?"). iPhone Safari gets install steps instead. At most once a fortnight; the source is logged on push_enable.
  • Playlists as landing pages: added to the sitemap, with an Open Graph cover image and ItemList structured data.
  • Share cards: a generated 1200×630 card per listing (real logo, deadline in Lagos time) is used when a listing has no picture. Shared links carry ?src=share, and listing pages have a WhatsApp button.
  • New listings with no views get 3× pick weight in the feed for 72 h. Their score is unchanged, and both Stories arms see the same feed.
  • Metrics added (funnel in the maintenance analytics): unique viewers per day, saves per day, sign-ups with verified and onboarded counts, 7-day return, and push open rate per kind (push links carry n=<log id> and the service worker reports taps).
