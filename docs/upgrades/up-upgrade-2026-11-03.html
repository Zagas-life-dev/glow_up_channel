Fixed by me

fixedEvery visitor shared one rate-limit bucket

No trust proxy was set, so on Cloud Run req.ip was Google's front end and not the visitor. Live proof: the limit is 5000 per 15 min, and RateLimit-Remaining dropped by 9 between two of my requests one second apart, so other people were spending my budget. At peak, everyone on an instance gets 429 at the same time.

Added app.set('trust proxy', 1) in server.js. Backend, minutes.

fixedPublic playlists loaded on every page, used by nothing live

The root PlaylistProvider fetched /api/playlists/public?limit=50 on every route for every visitor. That is 467 KB of JSON (50 KB brotli), 0.5–1.8 s on the backend, and about 56 Mongo ops. The only readers are the deprecated post composer and /post.

The context no longer fetches it on mount. The two composer screens fetch it when they open. contexts/playlist-context.tsx, components/post-composer.tsx, app/post/page.tsx.

fixedPlaylist creator lookups: one query per playlist → one query per page

/my, /shared, /public and /premium each ran a users.findOne for every playlist. Now there is one $in query through the withCreators() helper. The response shape is unchanged. /public goes from 50 queries to 1.

src/controllers/playlistController.js

fixed/my and /shared were fetched one after the other

Every signed-in page load waited for two round trips in series (≈600 ms at the 296 ms RTT measured earlier). They now run in parallel.

contexts/playlist-context.tsx

fixed3 background prefetches were thrown away every signed-in session

The prefetcher warmed the home tabs without a country. The home tab always sends the viewing country (auto mode has one from the timezone), and a country-limited page skips the cache. The test suite showed this: a default reader already has a country. The tabs are now warmed only in Anywhere mode. Tests updated, 7/7 pass.

lib/background-prefetch.ts, lib/background-prefetch.test.ts

fixedRetired Locked In cost a call on every signed-in page

LockedInProvider sat in the root layout and called getActiveLockedInSession() for every signed-in user. It also ran a 1 s re-render tick when a stale session existed. The provider now lives in app/locked-in/layout.tsx only.

fixedTracker-reminder cron scanned the whole collection 288×/day

The query is {status, reminderSentAt:null, reminderAt ≤ now} and no index covered it. I added {status:1, reminderSentAt:1, reminderAt:1} to src/config/database.js. Collection size not measured.

The index is only built when the startup index pass runs (see Needs you).

fixedFeed candidate pool cached per country

New src/services/candidatePoolCache.js: pools are cached per type + country for 45 s, concurrent misses share one read, and at most 64 pools are kept. Feed pages go from 4 Mongo reads to 0 on a hit. Job deadlines are re-checked on every read. 6 new tests.

fixedStartup no longer waits on indexes

Index creation runs after the DB connects without blocking listen, and runs per collection in parallel. 36 entries for dead collections removed (146 → 110). payments, subscriptions and hashtags were kept because live code still uses them. SKIP_INDEX_CREATION is unset on Cloud Run, so the new tracker index builds itself on the next deploy.

fixedSafe at 10 instances

Live max is 10, min 0: Cloud Run adds instances only under load. Mongo maxPoolSize went from 80 to 20 per instance (env MONGO_MAX_POOL_SIZE), so the worst case is 200 connections, not 800.

fixedPlaylist emails private

Creator, item-adder and collaborator emails are now blanked unless the reader is the owner or an accepted collaborator. This covers the list endpoints, the single playlist and Discover. The response shape is unchanged. 5 new tests.

fixedRender-blocking CSS cut by 75%

globals.css imported all nine Flaticon icon styles, though only solid-rounded and brands are used. Page CSS dropped from 192 KB to ~45 KB over the wire (1,269 KB → 349 KB raw) on every page. FlaticonStyle is now narrowed so an unloaded style fails the build.

not doneStatic pages

The root layout reads cookies and headers only to render the right language on the first paint. Making pages static would mean either a flash of the wrong language or putting the locale in the URL. fixedStatic pages

The root layout no longer reads cookies or headers. Locale and country come from cookies on the client; the middleware now also writes a glowup-country cookie. Static routes went from 0 to 75, including /, /jobs, /opportunities and /events (refreshed every 5 min). /jobs was verified to answer from cache. The listing pages (/jobs/[id] etc.) render once and are then cached for 5 min; verified MISS then HIT, with full content and JobPosting data in the HTML.

Trade-offs: a reader with a non-English language cookie gets English on the first paint only (most UI text isn't translated anyway, live included). If the backend fails while a listing page is being re-rendered, crawlers can see a page without the listing for up to 5 min; visitors still get it, because the browser loads it itself.

About 235 KB compressed per page (900 KB raw). Roughly half is Next.js + React itself, a fixed cost. The app's own biggest parts: the tag taxonomy (27 KB, used by on-device ranking), 162 icons (46 KB, already tree-shaken), places (9 KB), language files (3 KB each). Lazy-loading taxonomy and places would save ~35 KB (~15%), about a day of work. The real weight problem was the 192 KB of icon CSS, already fixed.
