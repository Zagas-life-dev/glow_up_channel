Fixed by me

fixedEvery visitor shared one rate-limit bucket

No trust proxy was set, so on Cloud Run req.ip was Google's front end and not the visitor. Live proof: the limit is 5000 per 15 min, and RateLimit-Remaining dropped by 9 between two of my requests one second apart, so other people were spending my budget. At peak, everyone on an instance gets 429 at the same time.

Added app.set('trust proxy', 1) in server.js. Backend, minutes.

fixedPublic playlists loaded on every page, used by nothing live

The root PlaylistProvider fetched /api/playlists/public?limit=50 on every route for every visitor. That is 467 KB of JSON (50 KB brotli), 0.5–1.8 s on the backend, and about 56 Mongo ops. The only readers are the deprecated post composer and /post.

The context no longer fetches it on mount. The two composer screens fetch it when they open. contexts/playlist-context.tsx, components/post-composer.tsx, app/post/page.tsx.

fixedPlaylist creator lookups: one query per playlist → one query per page

/my, /shared, /public and /premium each ran a users.findOne for every playlist. Now there is one $in query through the withCreators() helper. The response shape is unchanged. /public goes from 50 queries to 1.

src/controllers/playlistController.js

fixed/my and /shared were fetched one after the other

Every signed-in page load waited for two round trips in series (≈600 ms at the 296 ms RTT measured earlier). They now run in parallel.

contexts/playlist-context.tsx

fixed3 background prefetches were thrown away every signed-in session

The prefetcher warmed the home tabs without a country. The home tab always sends the viewing country (auto mode has one from the timezone), and a country-limited page skips the cache. The test suite showed this: a default reader already has a country. The tabs are now warmed only in Anywhere mode. Tests updated, 7/7 pass.

lib/background-prefetch.ts, lib/background-prefetch.test.ts

fixedRetired Locked In cost a call on every signed-in page

LockedInProvider sat in the root layout and called getActiveLockedInSession() for every signed-in user. It also ran a 1 s re-render tick when a stale session existed. The provider now lives in app/locked-in/layout.tsx only.

fixedTracker-reminder cron scanned the whole collection 288×/day

The query is {status, reminderSentAt:null, reminderAt ≤ now} and no index covered it. I added {status:1, reminderSentAt:1, reminderAt:1} to src/config/database.js. Collection size not measured.

The index is only built when the startup index pass runs (see Needs you).

To do next (ranked by impact ÷ size)

~2 hCache the feed candidate pool per country

Every feed page, including page 2+, re-reads up to 400 full listings per type with 4 finds, to serve 15–20 items. The pool depends only on country. Add an in-memory cache keyed by country||'*', 30–60 s TTL, with in-flight dedupe (same pattern as storyService.loadListings). That takes Mongo reads per page from 4 to 0 on a hit.

~30 minCold start waits for 141 index calls in series

createIndexes() awaits 141 createIndex calls one at a time before app.listen, and min-instances is 0. 44 of those are for deprecated collections (posts, channels, notifications, locked_in, wallet…). Fix: set SKIP_INDEX_CREATION=true on Cloud Run and run index creation once per deploy, or run them after listen in parallel. Delete the dead 44.

src/config/database.js:103, 147-466

a day+Every page is server-rendered on each request

The root layout reads cookies/headers for locale and country, so even /about and the policy pages are dynamic, at ≈400 ms TTFB. Move locale/country reading into the client providers, or into the pages that need it, so static pages can be cached at the edge.

app/layout.tsx:165

~1 hRoute-code prefetch runs twice

Each feed route's RSC payload is fetched twice per page: once by router.prefetch in BackgroundPrefetcher and once by the nav <Link> prefetch. That makes 12 requests where 6 would do. Also, /resources is prefetched while resources are paused. Measure on a local next start, then drop one of the two.

components/background-prefetcher.tsx:8, 38

~1 hAnonymous feed cache is a Mongo read every request

/api/feed/anonymous does a findOne for a 100-doc cache document each time, with no in-process memo and no Cache-Control. When the cache is stale, concurrent rebuilds can stampede. Add a memo + public, max-age=60. Low impact while visitors land on the marketing page.

src/services/publicFeedService.js:271

unverifiedJS weight 1.37 MB decoded per page

No heavy library (framer-motion, charts, genai) is imported by the app shell. The Turbopack build doesn't print first-load sizes, so a bundle analyzer run is needed to find what fills the 222 KB and 135 KB chunks.

Questions for you

  1. Privacy: /api/playlists/public returns each creator's email to anyone. Verified live; today the creators are @up.com accounts, but a user-made public list would expose a real email. The frontend uses createdBy.email as a fallback for owner checks and display names. My pick: drop email from the public and premium responses, and match owners by _id only.
