3. Conflicts between the two specs

  • Subscriptions data model. Creators spec: one subscriptions collection. Playlist spec: creator_subscriptions + users.savedPlaylists[].notify. Use the Playlist spec version (it says so itself). Playlist subscriber count = saves while public.
  • Subscriptions stage. Creators stage 2 is replaced by Playlist stage 2.
  • Member limits. Groups have no member limit; public collabs have max 5 earning members. Only enforced when a group goes public.
  • Cleanup. Both specs change the monthly cleanup. Do both rule changes in one edit.

4. Build order

Two lanes run side by side. Counting starts first because it needs a silent soak before money moves. Playlist features fill the soak window.

Lane A: counting → moneyP1 counting (soak) → P6 program + ledger → P7 payouts
Lane B: playlist featuresP0 removals → P2 rules → P3 subscriptions → P4 dashboard + requests → P5 groups + shared tracking

P0 · Removals ~half day

  • Delete glowScoreService, glowScoreConfig and every addXp call; remove XP UI (home, return sheet, profile).
  • Followers: drop showConnections. No migration needed (finding A).

Blocks nothing. Ship first: it shrinks the surface every later phase touches.

P1 · Unique view counting, silent 2-3 days build1-2 weeks soak

  • playlistViews: lifetime unique index (playlistId, viewerKey), written next to the existing daily ledger insert in playlistMetricsService.recordView. Device + user rows (finding B).
  • Drop unverified accounts, anon without valid cookie, owner/collabs, bots. Per-IP daily cap from programConfig.perIpDailyCap.
  • playlistStats: uniqueViews, views30d, lastViewAt, frozen.
  • playlists.publishedAt/unpublishedAt; private = frozen, no counting.
  • users.signupSourcePlaylistId + count signup as a view.
  • fraudFlags + spike detector (hourly, new accounts / same IP range). Ring detection can wait for P6.
  • programConfig collection seeded with all rates.

Depends on nothing. Starts the soak clock, so start it day 1 next to P0.

P2 · Public playlist rules + cleanup 1-2 days

  • Limit 5 public per creator (owner + accepted editor counts). 6th publish prompts "make one private".
  • Grandfather existing public lists; creators over 5 pick which 5 earn (earning flag).
  • Exclusions: premium, reserved Saved list, UP's own account.
  • Cleanup: lists with ledger rows go private, never deleted; groups with 2+ members skipped; nightly sweep logs removed items for the owner.

Needed by P5 (going public checks) and P6 (who earns).

P3 · Subscriptions + notification plumbing 3-4 days

  • notification_batches + 2h flush in the cron worker. Reused by groups.
  • Dispatcher types: playlist_update, creator_update (3/day ceiling), group_invite, group_activity, group_deadline. All outside the 5/day cap. Program types added in P6.
  • Save = subscribe: savedPlaylists[].notify, migration sets existing to false. PATCH /playlists/saved/:id/notify.
  • Triggers: items added, name/description change. Made private/deleted = drop subscribers silently.
  • creator_subscriptions + POST/DELETE /creators/:id/subscribe, "also their playlists" toggle, Subscribe on profile and card creator name.
  • Public subscriber counts; one notification settings screen.

P4 · Creator dashboard + listing requests 3 days

  • Analytics: unique viewers per list and total, progress to next 1,000, subscribers, top lists, traffic sources, active/inactive.
  • Non-member view: progress bar on best public list. Earnings panels added in P6.
  • listingRequests + admin review + notify both outcomes. Static "tips" content.

Needs P1 data and P3 counts. Doubles as the tool to eyeball soak numbers.

P5 · Groups, then shared tracking groups 3-4 daystracking 3 days

  • Groups: isGroup, invite link (7-day, revocable, joins as viewer), POST /playlists/join/:token, leave/remove, group_activity feed, batched activity pushes, going-public check against P2 limits, cleanup rule.
  • Status badge on every playlist item (can ship early; no group needed).
  • collaborators[].statusVisible, GET /playlists/:id/tracking with the simplified status map, direct Started/Submitted/Not for me via existing PATCH /:id/status with source: "group" and null clickedAt.
  • Daily deadline nudge (2 days out, once per item per member, replaces same-day started reminder).

Navigation placement on hold; build behind a direct route until the nav restructure lands.

P6 · Program + earnings ledger 5-7 days

  • creatorProgram, append-only earningsLedger (bonus, block, collab_share, reversal).
  • Block crediter: on each unique view, if uniqueViews crosses a block boundary, credit. Idempotent by (playlistId, blockNumber) unique index so nothing pays twice at 10 instances.
  • First-1,000 trigger: held 5,000, email + in-app popup, 7-day reminder, terms acceptance, release held on join.
  • Collab splits: even, round down, remainder to owner; non-member shares held.
  • Pending → available after holdDays (daily cron). Flagged lists pause crediting.
  • Dashboard earnings panel, block notifications, ring detection.

Gate: soak numbers signed off. Terms text must exist before launch.

P7 · Payouts 3-4 days

  • Bank details + optional TIN; Paystack resolve and name match vs typed name; fallback save if unresolvable; change re-checks and pauses that week.
  • Cash out at ≥ 5,000 available locks the amount; payoutRequests.
  • Admin weekly list, mark paid, notify + email. Tax as config percentage shown on statement.

Gate: accountant's tax rate (can ship at 0% pending, if allowed).

6. Decisions taken (recommended defaults, 10 Nov 2026)

  • The 9 fit rules: all accepted as written in the Creators spec.
  • Subscriptions: Playlist spec model wins (creator_subscriptions + savedPlaylists[].notify). Old connections rows (35, unread by any code) migrate into creator_subscriptions.
  • Collab first block: the 5,000 pool applies only if at least one earning member has not yet had a first bonus; otherwise the block pays 2,000 like any other.
  • Same device, second account: does not count. Accepted as anti-fraud.
  • Email for subscription and group notifications: none in v1 (push + inbox only).
  • Config: holdDays 7, perIpDailyCap 5, invite reminder 7 days, invite link expiry 7 days, taxRate 0 until the accountant confirms.
  • Nothing ships to production. All testing on localhost:3000 + a dev backend on :3002 pointed at glowup_dev, never glowup_channel.
