Work with us, so simple a child could fill it.

Today it is one menu of six options and then one long form (up to 11 boxes on a single screen). This proposal asks one easy question per screen, with big picture buttons, plain words and a check page before paying. Same data, same prices, same backend — only the way we ask changes.

What the research says

1One question per screen

GOV.UK found that asking one thing per page is easier for low-confidence users, works better on phones, and makes errors and saving progress simpler.

GOV.UK Design System — Question pages
2Fewer boxes, fewer drop-outs

Baymard: "too long / complicated" is a top reason people abandon, and most flows can show 20–60% fewer fields by default. We hide organisation, make deadline skippable and never ask twice.

Baymard Institute — checkout usability
3Choose, don't type

Picture tiles and chips ("Online", "Remote", "No deadline") beat empty boxes. Tapping is easier than spelling, especially on a phone.

NN/g — Children's UX; GOV.UK radios pattern
4The question is the heading

Big, plain question at the top ("What is the job called?") instead of a small label like "Title". Screen readers read it once.

GOV.UK — Question pages
5Show an example

Every typing box shows what a good answer looks like, so nobody freezes at a blank box.

NN/g — form design guidance
6Check before you pay

A "Check your answers" page with a Change link on every line. Tapping Change returns straight to the check page, not the start.

GOV.UK — Check answers pattern
7Kind error messages

Say what to do, not what went wrong: "Type the name so people know what it is", not "Title is required".

GOV.UK — Error message component
8A human is one tap away

"Ask a person" (WhatsApp) sits on every screen. Answers save as you go, so leaving never loses work.
